# M0.5 · Конфиг и логи · Конфиг из переменных окружения

**Фаза 1.** Нужно сначала: ничего.
**Результат:** сервер с пустым окружением падает сразу и печатает список **всех**
недостающих переменных, а не первой попавшейся.

Пакет: `backend/internal/config/` — отдельного пакета можно и не заводить, а сложить
всё прямо в `cmd/server`.

---

## Зачем это

Серверу нужно откуда-то узнать адрес базы, порт и секретный ключ. Вариантов два:
файл настроек в репозитории или переменные окружения. Берём переменные, и не из
моды: пароль базы и ключ подписи cookie в репозиторий попадать не должны, а
**секрет, попавший в историю git, оттуда уже не убирается** — его придётся считать
скомпрометированным и менять. Переменные окружения ровно этим и хороши: значение
живёт в `.env` (он в `.gitignore`) и в настройках окружения, а в коде остаётся
только имя.

Второй повод — момент падения. Опечатка в имени переменной даёт пустую строку, а не
ошибку. Без общего конфига это выглядит так: сервер стартовал зелёным, `/healthz`
отвечает 200, а первый игрок получает ошибку подключения к базе. Разница между «упал
на старте» и «упал на первом игроке» — это разница между «увидел в логе за секунду»
и «искал полчаса».

Третий: на конфиг завязаны сразу три задачи — [подключение к
Postgres](m05-db-connect.md) и [раннер миграций](m05-db-migrate-runner.md) из фазы 2,
[куки с подписью](m05-session-cookies.md) из фазы 1. Если каждая будет звать
`os.Getenv` у себя, одна и та же переменная окажется прочитана в трёх местах с
тремя разными умолчаниями.

---

## Что делаем

- [ ] Тип `Config` — все настройки сервера одной структурой
- [ ] Функция `Load() (Config, error)`: читает окружение, проверяет, возвращает
- [ ] Копить ошибки, а не возвращать первую — `errors.Join`
- [ ] Обязательные переменные — без умолчаний; необязательные — с явными
- [ ] Вызвать `Load()` в `main.go` **до** старта HTTP-сервера, упасть с `os.Exit(1)`
- [ ] Ни одного `os.Getenv` вне пакета конфига
- [ ] В лог не писать значения секретов
- [ ] Тесты на каждый случай: нет обязательной, мусор в булевой, всё на месте
- [ ] Дописать новые переменные в `.env.example` и прокинуть их в `docker-compose.yml`
      сервису `backend`: в контейнер попадает только то, что перечислено в его
      `environment`

## Что читаем из окружения

| переменная | обязательна | что это |
|------------|-------------|---------|
| `DATABASE_URL` | да | строка подключения к Postgres, см. [m05-db-connect.md](m05-db-connect.md) |
| `MIGRATE_ON_START` | нет, по умолчанию `false` | накатывать ли миграции при старте |
| ключ подписи cookie | да | HMAC-SHA256 для cookie игрока, см. [m05-session-cookies.md](m05-session-cookies.md) |
| `PORT` | нет, по умолчанию `8080` | уже читается в `main.go` |

Имени переменной под ключ подписи нигде нет — в
[m05-session-cookies.md](m05-session-cookies.md), раздел «Ключ подписи», сказано
только, что ключ «берётся из переменной окружения и в репозиторий не попадает
никогда». Придумать имя можно на месте, менять его потом дёшево.

Полного списка тоже нет: [stack.md](../stack.md), раздел «Что ещё смотрели и не
взяли», упоминает «семь переменных окружения», но не перечисляет их. Остальные
появятся по ходу — например, отдельный признак «это бой»,
чтобы ставить у cookie флаг `Secure`. Добавить переменную в готовый `Load()` — три
строки.

## `Config` и `Load`

```go
type Config struct {
    Port           string
    DatabaseURL    string
    MigrateOnStart bool
    CookieKey      []byte
}
```

Состав полей нигде не зафиксирован, это отправная точка. Важно другое: структура
одна, заполняется один раз при старте, дальше передаётся по значению. Никто в
середине партии не читает окружение заново — значит, состояние сервера не может
поменяться под ногами.

```go
func Load() (Config, error) {
    var cfg Config
    var errs []error

    cfg.DatabaseURL = os.Getenv("DATABASE_URL")
    if cfg.DatabaseURL == "" {
        errs = append(errs, errors.New("DATABASE_URL не задан"))
    }
    // ...остальные поля так же
    return cfg, errors.Join(errs...)
}
```

`errors.Join` собирает несколько ошибок в одну и печатает их по одной на строку. На
пустом срезе он возвращает `nil` — отдельной проверки «а были ли ошибки» писать не
надо.

Соблазн — `return cfg, err` на первой же непорядке. Тогда запуск на чистой машине
выглядит так: упало на `DATABASE_URL`, дописал, упало на ключе, дописал, упало на
третьей. Три ошибки — три круга по пересборке образа. С `errors.Join` круг один:

```
DATABASE_URL не задан
ключ подписи cookie не задан
MIGRATE_ON_START: "maybe" — нужно true или false
```

## Пустая строка — это не значение

`os.Getenv` не отличает «переменной нет» от «переменная есть и пустая»: в обоих
случаях `""`. Для обязательных полей разницы нет, обе ситуации — ошибка. Для
необязательных есть: `MIGRATE_ON_START=` должно дать умолчание, а не ошибку разбора.
Если различать нужно — `os.LookupEnv` возвращает вторым значением `bool`.

Булевы разбираем через `strconv.ParseBool`. Он понимает `1`, `t`, `T`, `true`,
`TRUE`, `True` и симметричные для лжи, а на всё остальное отдаёт ошибку. Ошибка тут
и нужна: своя проверка вида `v == "true"` на `MIGRATE_ON_START=1` тихо даст `false`,
миграции не накатятся, и разбираться придётся уже по симптому «таблиц нет».

## Грабли

Отдельного раздела «Грабли» под конфиг нет — они рассыпаны по задачам про базу
([m05-db-migrate-runner.md](m05-db-migrate-runner.md)) и про сессии
([m05-session-cookies.md](m05-session-cookies.md)).

**`MIGRATE_ON_START` по умолчанию `false`, а не `true`.** Умолчание срабатывает там,
где о переменной забыли. Забыть локально — партия не поднимется, потеря минута.
Забыть в бою при `true` — старый под при раскатке спокойно применит миграции из
файлов **нового** образа, и база уедет вперёд кода, который с ней работает.
[Advisory lock](../glossary.md#g-advisory-lock) в раннере
делает одновременный старт нескольких реплик безопасным, но не делает его
правильным: он защищает от того, чтобы две реплики накатили миграции одновременно, а
не от того, чтобы их накатила не та реплика. Поэтому: в `docker-compose.yml` для
локалки `true`, по умолчанию `false`, в бою — отдельный одноразовый сервис с
`depends_on: condition: service_completed_successfully`.

**У ключа подписи cookie умолчания быть не может.** Строчка вида
`if key == "" { key = "dev-secret" }` выглядит удобно ровно до первого боевого
запуска, где о переменной забыли: сервер поднимется и будет подписывать cookie
ключом, который лежит в публичном репозитории. Подделать `player_id` сможет кто
угодно, а по логам всё выглядит штатно. Нет ключа — падаем.

**Конфиг целиком в лог не пишем.** `log.Info("config", "cfg", cfg)` выведет
`DATABASE_URL` вместе с паролем и ключ подписи — в stdout, а оттуда в любой сборщик
логов, откуда их уже не вычистить. Логировать можно порт и `MIGRATE_ON_START`; про
секреты — только факт «задан».

**`viper` тут не нужен.** Это 17 [модулей](../glossary.md#g-module)
ради семи переменных, и главное — его `GetString` на отсутствующем ключе возвращает
`""` вместо ошибки. То есть библиотека делает ровно то, от чего эта задача защищает.
`os.Getenv` + `errors.Join` — [стандартная
библиотека](../glossary.md#g-stdlib), ноль зависимостей.

## Готово, когда

- [ ] `go build -o /tmp/server ./cmd/server && env -i /tmp/server` печатает **все**
      недостающие переменные списком и завершается; `echo $?` даёт не ноль. Через
      `env -i go run` не выйдет: без `PATH` и `HOME` не запустится сам `go`
- [ ] Задал одну из них — в списке остались ровно остальные
- [ ] `curl localhost:8080/healthz` после такого падения даёт `Connection refused`:
      порт не открывался вообще
- [ ] `MIGRATE_ON_START=maybe` — ошибка с именем переменной и её значением, а не
      тихий `false`
- [ ] `go test ./internal/config/...` зелёный
- [ ] `docker compose up` поднимается как раньше, `/healthz` отвечает
- [ ] В `.env.example` есть все новые переменные с заведомо игрушечными значениями

Тесты тут удобно писать
[таблицей](../glossary.md#g-table-test): строчка на случай —
«набор переменных → ожидаемый конфиг или ожидаемый кусок текста ошибки». Окружение в
тестах ставить через `t.Setenv`, а не `os.Setenv`: он сам возвращает прежнее
значение после теста и роняет тест, если тот помечен
[`t.Parallel()`](../glossary.md#g-tparallel) — иначе
параллельные тесты растащили бы окружение процесса друг у друга.
