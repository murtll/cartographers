# M0.5 · Планшеты · Разметка планшетов

**Фаза 1.** Нужно сначала: ничего.
**Результат:** сервер знает, где на поле горы, руины и ущелья, и отказывается стартовать
с битым файлом разметки.

Пакет: `backend/internal/boards/`.

---

## Зачем это

В настольной игре каждый игрок получает бумажный лист — **планшет картографа**. В центре
листа поле 11×11, на котором рисуют, оно называется **карта владений**. Часть клеток
занята заранее, типографией: горы, руины и ущелья. Подробнее про сами правила —
[docs/game-rules.md](../game-rules.md).

Эти три списка клеток и есть «разметка планшета». За партию она не меняется ни на клетку.

Почему с неё удобно начинать:

1. **Без неё сервер не может проверить ход.** «Клетка свободна» раскладывается в «игрок
   туда ещё не рисовал **И** там не гора **И** там не ущелье». Первое лежит в состоянии
   партии, второе и третье — только в разметке.
2. **Без неё нечего показывать.** Пустая клетчатая сетка — это не игра.
3. Это первые настоящие данные в проекте, и первое, что можно молча испортить опечаткой.

## Формат: картинкой, а не координатами

```json
{
  "id": "wildlands",
  "name": "Wildlands",
  "grid": [
    "...........",
    "....M......",
    "..R........",
    "...........",
    "...........",
    ".....M.....",
    "...........",
    "...........",
    "........R..",
    "......M....",
    "..........."
  ]
}
```

Один символ — одна клетка:

```
.  обычная клетка, рисовать можно
M  гора      (mountain)
R  руины     (ruins)
C  ущелье    (chasm)
```

Напрашивается вместо этого список координат — `"mountains": [[1,3],[2,8]]`. Картинка
лучше по четырём причинам:

- **Её видно глазами.** В списке координат ошибку «гора не в той строке» не заметит
  никто и никогда.
- **Размер проверяется сам.** Одиннадцать строк по одиннадцать символов — и всё. В
  списке координат надо отдельно проверять, что никто не вылез за `0..10`.
- **«Клетка объявлена дважды» становится невозможной.** В одной позиции ровно один
  символ. Целое правило проверки просто исчезает.
- **Diff в git читается.** Подвинул гору — видно одну строку и один символ.

Минус ровно один: разбирать чуть длиннее, строк десять кода. Клеток тут 121, экономить
на разреженности нечего.

## Структуры в Go

```go
type Cell uint8

const (
    CellPlain    Cell = 0 // рисовать можно
    CellMountain Cell = 1 // нельзя, но даёт монету когда окружена
    CellRuins    Cell = 2 // рисовать можно; до этого считается незаполненной
    CellChasm    Cell = 3 // нельзя, только на стороне Б
)

type Grid [11][11]Cell // [строка][столбец], с нуля, строка 0 — верхняя

type Board struct {
    ID   string `json:"id"`
    Name string `json:"name"`
    Grid Grid   `json:"grid"`
}
```

`[11][11]Cell` — [массив](../glossary.md#g-array-slice), не срез.
Размер известен на этапе компиляции, значит никаких `nil`, никаких проверок длины, и
копируется он обычным присваиванием.

`Cell uint8` с явными значениями — это перечисление: свой тип поверх числа, чтобы нельзя
было по ошибке передать туда произвольное число или перепутать с типом местности.

`Grid` — отдельный тип со своим `UnmarshalJSON`: в файле `grid` лежит как 11 строк, а не
как двумерный массив `Cell`. `UnmarshalJSON` сперва разбирает JSON в `[11]string`, потом
зовёт `parseBoard`, которая раскладывает символы `.MRC` по клеткам.

Файлы вшиваем в бинарник:

```go
//go:embed *.json
var jsonFiles embed.FS
```

Так образ остаётся однофайловым, и не бывает ситуации «забыл скопировать `data/` в
Docker-образ, локально работает, в контейнере нет». Именно поэтому `.json` лежат в одном
каталоге с `boards.go`: [`//go:embed`](../glossary.md#g-embed) не
умеет ходить вверх по дереву, `../data/` он не соберёт.

## Что проверяет загрузчик

Плохой файл — сервер **не стартует**. Молча подставлять умолчания нельзя: тихо поехавшая
разметка это худший вид бага — всё работает и всё неправильно.

- [ ] ровно 11 строк в `grid`
- [ ] в каждой строке ровно 11 символов — считать **[руны](../glossary.md#g-rune), а не байты**
- [ ] символы только из `.MRC`
- [ ] `id` совпадает с именем файла

Про руны отдельно. Если в файл попадёт кириллическая `С` вместо латинской `C`, то `len()`
по строке покажет 12, а не 11: в UTF-8 кириллическая буква занимает два байта. Ошибка
получится про длину строки, а искать надо будет символ. Поэтому длину считаем в рунах —
`utf8.RuneCountInString` или обход через `range`.

Про `id` тоже не зря: иначе однажды в `wasteland.json` окажется `"id": "wildlands"`, и
полдня уйдёт на «почему грузится не та карта».

Текст ошибки — с файлом, строкой и позицией:

```
wasteland.json: строка 4, позиция 7: неизвестный символ 'X'
```

Не `invalid board`. Разница в том, сколько времени займёт починка: в первом случае секунды,
во втором — полчаса с распечаткой файла.

## Координаты пока выдуманные

Расположение гор и руин в примере выше придумано. В тексте правил его нет: планшет там
показан картинкой, а не описан словами. Настоящие координаты надо снять со скана.

Там же и размер: 11×11 в тексте правил тоже не написано, это известно по картинке.

На эту задачу оно не влияет. Формат не изменится, поменяются символы внутри строк.

## Готово, когда

- [ ] Тест грузит оба файла и не падает
- [ ] Тест на битые файлы, на каждый случай свой: 10 строк вместо 11, строка на 12
      символов, неизвестная буква. Каждый даёт **свою** ошибку, а не
      одну общую
- [ ] Испортил символ в `wasteland.json` — `go run ./cmd/server` падает до открытия порта
      и пишет, что именно не так

Тесты тут удобно писать [таблицей](../glossary.md#g-table-test):
на каждый битый случай строчка «вход → ожидаемый кусок текста ошибки». Тогда добавить
новую проверку — это добавить строчку, а не скопировать функцию.
