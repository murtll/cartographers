# M0.5 · Комната · Проекция: что видит игрок

**Фаза 3.** Нужно сначала: [m05-room-fold.md](m05-room-fold.md).
**Результат:** в JSON, который уходит игроку, физически нет порядка колоды — и на это
есть тест.

Пакет: `backend/internal/room/`. Раздел плана: «Шаг 6. Пакет `room` — актор, свёртка,
проекция», строки 1227–1258 и 1299–1306.

---

## Зачем это

[Свёртка](../plans/20260728-cartographers-m05.md#g-fold) даёт состояние комнаты целиком:
поле, счётчики, игроки — и вместе с ними порядок колоды из события `game_started`.
Отдавать это состояние в браузер как есть нельзя.

Проекция — функция, которая берёт состояние и собирает из него
[снапшот](../plans/20260728-cartographers-m05.md#g-snapshot) для конкретного игрока.
Секрет здесь один: порядок колоды. В [логе](../plans/20260728-cartographers-m05.md#g-log)
он есть, в браузер не уезжает. Иначе игрок открывает инструменты разработчика и видит
будущее.

Что не работает, пока этой задачи нет:

1. **Рассылать подписчикам нечего.** В структуре комнаты стоит
   `subscribers []chan Snapshot` — по каналу уезжает именно `Snapshot`, и его надо из
   чего-то собрать. [m05-room-subscribers.md](m05-room-subscribers.md) начинается там,
   где эта задача кончается.
2. **У фронтенда нет эталона.** Имена полей план фиксирует, а вот JSON, против которого
   проверяются типы TypeScript, пишет тест из этой задачи.
3. **Утечку потом не вычистить.** Научится снапшот возить лишнее — убирать это придётся
   уже из написанного браузера.

---

## Что делаем

- [ ] Тип `Snapshot` — ровно поля из JSON ниже, с тегами `json:"..."`
- [ ] Метод `project(playerID)` — собирает `Snapshot` из состояния комнаты
- [ ] Пустая клетка — строка `"empty"`
- [ ] Разметку планшета в снапшот не класть, только `board_id`
- [ ] Порядок колоды и `seed` — в неэкспортируемое поле состояния
- [ ] Тест: `game_started` в проекцию не попадает
- [ ] Тест: в готовом JSON нет запрещённых подстрок
- [ ] В логах — только `room_code`, `seq`, `type`, без payload событий

## Что уезжает в браузер

Дословно из плана:

```json
{
  "seq": 42,
  "phase": "cartography",
  "round": 7,
  "deadline": "2026-07-28T12:00:30Z",
  "you": "p1",
  "board_id": "wildlands",
  "options": [{ "shape_id": "single", "terrains": ["forest", "village"] }],
  "constraint": null,
  "boards": {
    "p1": {
      "drawn": [
        ["empty", "empty", "forest", "..."],
        ["empty", "village", "empty", "..."]
      ],
      "coins": 0
    }
  },
  "players": [{ "id": "p1", "name": "Ваня", "submitted": false }],
  "deck_remaining": 9
}
```

Что каждое поле значит по правилам — таблица «Что видит браузер» в
[game-rules.md](../game-rules.md). Тут только то, что важно для сборки:

- `seq` — номер последнего применённого [события](../plans/20260728-cartographers-m05.md#g-seq).
  Браузер его помнит и при обрыве просит «всё, что после 17». Поставишь сюда что-то
  своё — сломается переигровка, а не отображение, и заметно это будет не сразу.
- `you` — кто из игроков получатель. Из-за этого поля проекция и делается на игрока, а
  не одна на комнату.
- `deadline` — абсолютное время. Отсчёт рисует браузер, решение «время вышло»
  принимает сервер: часы на машине игрока могут быть любыми.
- `deck_remaining` — **сколько** карт осталось. Не секрет. Секрет — **какие** и в каком
  порядке.
- `options` и `constraint` — то, что открыла карта текущего раунда. Она открыта для
  всех, прятать нечего. В M0.5 `shape_id` всегда `"single"`, `constraint` всегда пустой.

## Типы в Go

```go
type Snapshot struct {
    Seq   int64  `json:"seq"`
    Phase string `json:"phase"`
    You   string `json:"you"`
    // остальные поля — ровно как в JSON выше
}

func (r *Room) project(playerID string) Snapshot
```

`Snapshot` — это тот же тип, что стоит в `subscribers []chan Snapshot`. Значит он
уезжает по [каналу](../plans/20260728-cartographers-m05.md#g-channel) в чужую
[горутину](../plans/20260728-cartographers-m05.md#g-goroutine). Отсюда правило: проекция
**копирует**, а не отдаёт ссылку на состояние. `drawn` собирается новым срезом строк
прямо в `project`. Если вместо этого вернуть срез, который смотрит в состояние комнаты,
получится [гонка](../plans/20260728-cartographers-m05.md#g-race): актор правит поле, а
подписчик его в этот момент читает.

`project` — с маленькой буквы и метод. Зовут его только из `run()`, изнутри
[актора](../plans/20260728-cartographers-m05.md#g-actor). Экспортировать нельзя: тогда
кто-нибудь позовёт его из HTTP-обработчика напрямую, мимо канала, и весь смысл одной
горутины на комнату исчезнет.

`playerID` в подписи нужен сейчас, хотя комната в M0.5 всегда на одного и ответ пока
один и тот же. Добавить аргумент потом — это переписать всех вызывающих.

---

## Что решено заранее

**Пустая клетка — явное `"empty"`, не `null` и не пропуск.** Иначе в браузере начнутся
проверки на пустоту на каждом шагу.

**Разметка поля не ездит в снапшоте** (договорённость 5 плана, строки 623–628). Горы,
руины и ущелья напечатаны на [планшете](../plans/20260728-cartographers-m05.md#g-planshet)
и за партию не меняются. Браузер забирает их один раз через `GET /api/boards/{id}` и
держит фоном. Отсюда неочевидное следствие: клетка с горой приезжает в `drawn` как
`"empty"` — в `drawn` только то, что игрок нарисовал сам. Соблазн «заодно проставить
горы, чтобы фронту было проще» надо давить: тогда одна и та же клетка описана в двух
местах, и однажды они разойдутся.

**Снапшот целиком, а не разница.** Партия это ~2 КБ, событий за игру ~35. Экономить
нечего, кода вдвое меньше, склеивать патчи на клиенте не надо.

## Грабли

Раздел «Грабли» у шага 6 общий на весь пакет `room`. Медленный подписчик и порядок
«подписаться → доотправить» — это [m05-room-subscribers.md](m05-room-subscribers.md),
тесты на таймеры через `testing/synctest` — [m05-room-deadline.md](m05-room-deadline.md).
Сюда относится последнее, и оно же самое важное.

**Одного [golden-теста](../plans/20260728-cartographers-m05.md#g-golden) мало.** У таких
тестов есть флаг «перезаписать образцы», и `go test -update` спокойно перезапишет эталон
вместе с утечкой. Тест позеленеет. На ревью это выглядит как обычный шум в diff'е
эталонного файла — ровно то, что глаз пролистывает.

Поэтому три слоя вместо одного.

*Слой первый — колода лежит в неэкспортируемом поле.* Например `deckOrder`, с маленькой
буквы. `encoding/json` неэкспортируемые поля не сериализует вообще, так что даже
случайный `json.Marshal` состояния её не покажет. А проекция собирает отдельный тип
руками, поле за полем: новое поле в состоянии само по себе в снапшот не проваливается.

*Слой второй — тупая проверка «в готовом JSON нет вот этих подстрок».* Маршалим
снапшот, ищем в байтах имена полей (`deck_order`, `seed`) и сами значения из фикстуры.
`-update` такую проверку подделать не может: она сравнивает не с файлом, а с
константами в тесте. Фикстуру стоит сделать приметной, чтобы значения нельзя было
спутать с чем-то законным. Ловит она ровно то, что перечислено, — список пополняется
вместе с секретами.

*Слой третий — в логи не пишем payload событий целиком, только `room_code`, `seq`,
`type`.* Лог — это тот же канал утечки, просто медленнее: строчку с payload'ом
`game_started` кто-нибудь вставит в issue или покажет на экране. И отдельно про `seed`:
если перемешивание детерминированное, по одному seed'у колода восстанавливается
целиком. Прятать `deck_order`, но возить `seed`, — это не прятать ничего.

## Чего ещё не решено

- **Формат идентификатора игрока.** `"p1"` в плане — пример, чтобы короче читалось.
- **Список значений `phase`.** В примере `"cartography"`; какие ещё бывают в M0.5 —
  в плане не зафиксировано.
- **Как считается `deck_remaining`.** Числа в примере иллюстративные: при 12 раундах
  `round: 7` и `deck_remaining: 9` вместе не сходятся.
- **Где вызывается `json.Marshal`** — в `room` или в `api`. Тест проекции всё равно
  маршалит сам, иначе проверять подстроки не в чем.

## Готово, когда

- [ ] `go test ./internal/room/ -run TestProjection -v` — зелёный
- [ ] Тест: применили `game_started` с приметным порядком колоды, спроецировали,
      в JSON этих строк нет
- [ ] Тест: пустая клетка приезжает как `"empty"`, клетка с горой — тоже как `"empty"`,
      значения `mountain` в `drawn` нет нигде
- [ ] `go test -race ./...` молчит — значит снапшот действительно копия
- [ ] Временно добавил в `Snapshot` поле с колодой — подстроковый тест краснеет, и
      `go test -update` его не чинит
- [ ] Когда появятся ручки ([m05-http-api.md](m05-http-api.md)):

```sh
curl -N localhost:8080/api/rooms/ABCD/stream | grep -n 'deck_order\|seed'
```

Ничего не напечаталось — всё в порядке.

Тесты тут удобно писать
[таблицей](../plans/20260728-cartographers-m05.md#g-table-test): вход — список событий,
ожидание — кусок готового JSON.
