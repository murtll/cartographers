# M0.5 · HTTP · Роутер и пять путей

**Фаза 1.** Нужно сначала: ничего.
**Результат:** все пять путей отвечают заглушками, неизвестный путь даёт JSON-404, а не
HTML.

Пакет: `backend/internal/api/`. Раздел плана: «Шаг 7. Пакет `api` — HTTP и SSE».

---

## Зачем это

Сейчас сервер умеет один путь — `GET /healthz`, и живёт он прямо в `cmd/server/main.go`.
Пакета `internal/api/` ещё нет. Настоящих путей в M0.5 пять, и ни одного из них сервер не
знает.

Задача — построить таблицу путей и посадить за неё заглушки. Никакой игры, никакой базы:
на каждый путь ответ-константа правильной формы.

Почему это первое, что делают в теме HTTP:

1. **Дальше всё вешается сюда.** Логи и перехват паники оборачивают роутер целиком
   ([m05-http-middleware.md](m05-http-middleware.md)). Поток событий — это один из этих
   пяти путей ([m05-http-sse.md](m05-http-sse.md)). Настоящие
   [ручки](../plans/20260728-cartographers-m05.md#g-handler) заменяют заглушки по одной,
   не трогая таблицу ([m05-http-api.md](m05-http-api.md)).
2. **URL перестают быть словами на бумаге.** Их можно дёргать `curl`-ом сегодня, а
   браузерная часть может писать запросы против настоящих адресов до того, как за ними
   что-то появится.
3. **Здесь решается, что сервер отвечает на чужой запрос.**
   [Статус](../plans/20260728-cartographers-m05.md#g-status) и `Content-Type` у ошибки —
   такая же часть API, как успешный ответ. Ошибку в них замечают позже всех: с виду
   работает, а фронтенд падает в непонятном месте.

## Пять путей

```
POST /api/rooms                 создать комнату, вернуть код
POST /api/rooms/{code}/join     ник → cookie с местом игрока
GET  /api/rooms/{code}/stream   SSE: поток снапшотов
```

Это весь HTTP-API этапа. Последний путь отдаёт разметку планшета из
[m05-boards-markup.md](m05-boards-markup.md), остальные четыре — про комнату.

## Роутер встроенный, библиотеки нет

`ServeMux` с Go 1.22 умеет метод и параметр прямо в шаблоне:

```go
mux := http.NewServeMux()
mux.HandleFunc("POST /api/rooms/{code}/moves", h.submitMove)
```

Внутри ручки код комнаты достаётся как `r.PathValue("code")`.

Метод пишем в шаблон, а не проверяем `if r.Method != http.MethodPost` внутри ручки. Разница
в том, что mux сам отдаёт 405 с [заголовком](../plans/20260728-cartographers-m05.md#g-headers)
`Allow`. Проверка руками — это пять одинаковых `if`, и `Allow` в них забудут все пять раз.

Порядок регистрации не важен: mux выбирает самый специфичный подходящий шаблон. А два
шаблона, из которых ни один не специфичнее другого, — это паника при регистрации, то есть
на старте сервера, а не на запросе от игрока.

[Библиотеку](../plans/20260728-cartographers-m05.md#g-library)-роутер не берём, разбор есть
в плане, раздел «Почему нет роутера». Коротко: `chi` — честный второй номер, но всё, ради
чего его берут (группы, монтирование подроутеров, свои обработчики 404/405), на пяти
плоских ручках не нужно. `gin` тащит ассемблерный JSON-JIT, quic-go, protobuf и драйвер
mongo. `echo` заменяет `http.Handler` на свой тип. `fiber` вообще не на `net/http` — там
нет ни `http.Flusher`, ни `ResponseController`, то есть
[SSE](../plans/20260728-cartographers-m05.md#g-sse) пришлось бы писать по-другому.

## Что возвращает сборка роутера

Возвращаем `http.Handler`, а не `*http.ServeMux`. Следующая задача обернёт результат
[middleware](../plans/20260728-cartographers-m05.md#g-middleware), и `main.go` от этого не
поменяется ни строкой.

Что ручки будут держать общего — пул соединений к базе, реестр комнат, ключ подписи — ещё
не решено, это появится вместе с ними в [m05-http-api.md](m05-http-api.md). Пока состояния
у заглушек нет вовсе.

Хелпер записи ответа нужен сразу, хотя выглядит преждевременно. Он ставит `Content-Type`,
пишет статус и кодирует тело — три строки, которые иначе будут скопированы в пять мест и в
одном из них разъедутся. Точная форма объекта ошибки в плане не зафиксирована; важно, что
она одна и та же у всех путей, включая 404 от роутера.

## Чем отвечают заглушки

- `POST /api/rooms` → 200 и `{"code":"ABCD"}`. Код здесь константа. Как коды генерируются
  и какой они длины — [m05-session-room-codes.md](m05-session-room-codes.md), в плане это
  ещё не решено.
- `POST /api/rooms/{code}/join` → 200. [Cookie](../plans/20260728-cartographers-m05.md#g-cookie)
  заглушка не ставит: подпись — [m05-session-cookies.md](m05-session-cookies.md).
- `POST /api/rooms/{code}/moves` → 200 и пустой объект. Тело запроса пока не разбираем.
- `GET /api/boards/{id}` → 200 и пустой объект. Настоящую разметку сюда положат, когда
  будет загрузчик.
- `GET /api/rooms/{code}/stream` → 200 и `Content-Type: text/event-stream`, один кадр,
  потом закрыть. Единственная заглушка не про JSON, и это осознанно: `EventSource` в
  браузере умирает от любого не-200 **и** от неправильного `Content-Type` — навсегда, без
  повторных попыток. Отдай заглушка `application/json` — подключённый к этому пути
  фронтенд будет молча мёртвым, и причину в нём же и будут искать.

## Грабли

**Catch-all на `/` отдаёт HTML в ответ на JSON-запрос со статусом 200.** Это про шаг 9
плана, когда бэкенд начнёт раздавать собранный фронтенд, но обработчик `/` появляется
здесь, поэтому и проверка пишется здесь.

Механизм. Шаблон `/` подходит к любому пути и к любому методу. Автоматический 405 у mux
срабатывает, только когда по методу не подошло **ничего** — а с зарегистрированным `/`
такого не бывает никогда. В итоге `DELETE /api/rooms` и `GET /api/rooms/{code}/moves`
уезжают в заглушку, и вместо 405 приходит 200 с `index.html`. На стороне браузера
`res.json()` падает с `Unexpected token '<'`. Каждая опечатка в URL становится непонятным
крашем фронта, и искать её будут в JavaScript, хотя сломан роутинг.

Лечится проверкой префикса в самой заглушке:

```go
if strings.HasPrefix(r.URL.Path, "/api/") {
    // честный JSON-404
}
```

Что при этом меняется: 405 на путях `/api/*` исчезает, его перехватывает та же заглушка, и
на чужой метод приходит «нет такого пути» вместо «сюда так нельзя». Цена мелкая — и 404, и
405 одинаково честный не-200, клиент видит статус и не пытается разбирать тело как ответ.
Беда была именно в 200.

**Стандартный 404 — это текст, а не JSON.** `http.NotFound` пишет `404 page not found` с
`Content-Type: text/plain; charset=utf-8`; встроенный 405 от mux устроен так же. То есть
«JSON-404» — это не «ничего не делать», а свой ответ через тот же хелпер, что и у ручек.
Иначе на `/api/*` живут два разных формата ошибки: JSON из ручек и текст из роутера, и
разбирать их на фронте придётся по-разному, глядя на статус.

## Готово, когда

- [ ] `go run ./cmd/server` поднимается, `/healthz` по-прежнему отдаёт `{"status":"ok"}`
- [ ] Все пять путей отвечают:

```sh
curl -i -X POST localhost:8080/api/rooms
curl -i -X POST localhost:8080/api/rooms/ABCD/join
curl -i -X POST localhost:8080/api/rooms/ABCD/moves
curl -i localhost:8080/api/boards/wildlands
curl -i -N localhost:8080/api/rooms/ABCD/stream
```

  В каждом ответе видно 200 и `Content-Type`: `application/json` у четырёх, у потока
  `text/event-stream`.

- [ ] `curl -i localhost:8080/api/nope` → 404, и тело начинается с `{`, а не со слов
      `404 page not found`
- [ ] `curl -i localhost:8080/api/rooms/ABCD/moves` — GET на POST-путь. Не 200 и не HTML
- [ ] `curl -i -X DELETE localhost:8080/api/rooms` — тоже не 200
- [ ] Тест достаёт код из пути: запрос на `/api/rooms/ABCD/moves` — ручка видит `ABCD`
      в `r.PathValue("code")`
- [ ] `go test ./internal/api/` зелёный

Тесты тут удобно писать [таблицей](../plans/20260728-cartographers-m05.md#g-table-test): в
строке метод, путь, ожидаемый статус и ожидаемый `Content-Type`. Тогда новый путь — это
новая строка, а не скопированная функция. Сервер для этого поднимать не обязательно:
`httptest.NewRecorder()` и вызов роутера напрямую делают то же самое и быстрее.
