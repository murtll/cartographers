## Зачем это

CI — это чужая машина, которая на каждый push запускает те же команды, что запускаются
перед коммитом. Ценность не в командах, а в слове «каждый»: проверку, которую надо помнить,
однажды забывают, и обычно в тот коммит, где она бы сработала.

Три вещи, которые без CI ловятся случайно или не ловятся вовсе:

1. **[Гонки](../plans/20260728-cartographers-m05.md#g-race).** С фазы 3 у каждой комнаты своя
   [горутина](../plans/20260728-cartographers-m05.md#g-goroutine). Гонка без
   [детектора](../plans/20260728-cartographers-m05.md#g-race-detector) проявляется раз в неделю
   и невоспроизводимо, а `go test -race ./...` ловит её сразу — если его запустить.
2. **Протечка слоёв в `internal/game`.** Правила не знают ни про HTTP, ни про базу. Нарушается
   это не строчкой `import "net/http"`, а через третий пакет, молча.
3. **Расхождение Go и TypeScript.** [Кодогенерацию](../plans/20260728-cartographers-m05.md#g-codegen)
   мы не берём, значит переименование поля в Go ничего не ломает: фронт молча отрисует
   `undefined`.

Вторая половина задачи — чек-лист неприятных случаев: ручной прогон в браузере. Он
единственный смотрит на систему целиком: закрытая вкладка, пропавший вайфай, перезапуск
контейнера. Ни один `go test` этого не покрывает.

## Что именно гоняет CI

```sh
test -z "$(gofmt -l .)"
go vet ./...
golangci-lint run
go test -race ./...
```

Всё это — **из каталога `backend/`**. В корне репозитория `go.mod` нет, поэтому оттуда любая
команда с `./...` упрётся в:

```
pattern ./...: directory prefix . does not contain main module or its selected dependencies
```

В workflow это либо `working-directory: backend`, либо `go -C backend`. Ошибка выглядит
страшно и означает только «не тот каталог».

Порядок не случайный: сначала дешёвое, потом тесты. Красный формат виден через десять секунд,
а не через три минуты.

`golangci-lint` ставится **бинарником**, а не через `go install` в зависимости проекта: иначе
линтер попадает в [`go.mod`](../plans/20260728-cartographers-m05.md#g-gomod) и тянет полсотни
чужих модулей в зависимости сервера. Версия
[прибита](../plans/20260728-cartographers-m05.md#g-version) — `v2.12.2` — чтобы прогон через
полгода дал то же самое, а не покраснел на неизменившемся коде из-за новой проверки.

## Тест на чистоту `internal/game`

`internal/game` не импортирует ни HTTP, ни базу: правила — чистые функции, дали состояние и
ход, вернули новое состояние или ошибку. Тестируются без сервера и без базы.

Проверка — прогнать `go list -deps ./internal/game/...` и упасть, если в списке появились
`net/http` или [драйвер](../plans/20260728-cartographers-m05.md#g-driver) базы. `-deps`
печатает не прямые импорты, а всё замыкание: то, что пакет тянет за собой через чужие пакеты.
Примерно так:

```go
func TestGameStaysClean(t *testing.T) {
    out, err := exec.Command("go", "list", "-deps",
        "github.com/murtll/cartographers/backend/internal/game/...").Output()
    if err != nil {
        t.Fatal(err)
    }
    for _, dep := range strings.Fields(string(out)) {
        if dep == "net/http" || strings.HasPrefix(dep, "github.com/jackc/pgx") {
            t.Errorf("internal/game тянет %s", dep)
        }
    }
}
```

Двенадцать строк. Путь пакета здесь полный, а не `./internal/game/...` как в команде выше:
тест запускается из каталога своего пакета, и относительный шаблон оттуда не разрешится.
Список запрещённых префиксов пополняется руками — это его единственная слабость, и она
честная.

Зачем такой тест, если у линтера есть готовое правило `depguard`: **`depguard` видит только
прямые импорты**. Функция вида `func Score(d *store.DB) int` пройдёт его с нулём замечаний,
хотя через `internal/store` в `game` уже приехал pgx. Линтер оставляем ради быстрой обратной
связи — он ругается в редакторе, а не через три минуты в CI, — но настоящая проверка это
`go list -deps`.

Цена нарушения не абстрактная: как только в `game` приехал драйвер, тесты правил начинают
требовать поднятый Docker и старт контейнера.

В плане это же записано и в открытые вопросы: останется ли `internal/game` чистым, когда
дойдём до подсчёта очков. Тест заставит, но если подсчёту понадобится порядок колоды или
лента событий — слои придётся перекладывать. Это ещё не решено.

## Чек-лист неприятных случаев

Восемь пунктов, руками, в браузере. Ни один из них не тест на Go — они пересекают все слои
сразу, от куки до базы:

- [ ] Закрыть вкладку посреди партии, открыть заново → то же состояние
- [ ] Выключить вайфай на 20 секунд, включить → браузер догнал пропущенное
- [ ] Перезапустить контейнер бэкенда → партия жива
- [ ] Кликнуть по клетке два раза быстро → один ход
- [ ] Отправить ход за закрытый раунд → сервер игнорирует
- [ ] Отправить неправильный ход (за границу, на гору) → внятная ошибка, сервер не падает
- [ ] Дать таймеру истечь → сервер поставил клетку сам
- [ ] Открыть комнату в двух вкладках → обе видят одно и то же

Каждый пункт бьёт в конкретное место. «Партия жива после перезапуска» — что
[источник истины](../plans/20260728-cartographers-m05.md#g-truth) лежит в базе, а не в памяти
процесса. «Догнал пропущенное» — что [переигровка](../plans/20260728-cartographers-m05.md#g-replay)
по [`seq`](../plans/20260728-cartographers-m05.md#g-seq) работает. «Два клика — один ход» — что
[актор](../plans/20260728-cartographers-m05.md#g-actor) складывает запросы в очередь и второй,
пришедший уже за закрытый раунд, молча выбрасывается, а не рисует вторую клетку.

Девятый пункт из шага 8: сыграть партию целиком, потом devtools → Network, найти поток и
убедиться, что порядка колоды в нём нет.

## Грабли

Отдельного раздела «Грабли» под шаг 10 в плане нет. Здесь собрано то, из-за чего CI бывает
зелёным на сломанном коде — это хуже, чем красный CI на рабочем.

**`gofmt -l` завершается успешно всегда.** Он печатает список неотформатированных файлов, но
код возврата у него нулевой. В цепочке через `&&` он ничего не остановит, и прогон пройдёт
зелёным с криво отформатированным кодом. `test -z "$(gofmt -l .)"` превращает «список
непустой» в настоящую ошибку. Это единственная команда из четырёх, которую нельзя писать
наивно.

**Зелёный `go test ./...` может ничего не значить.** Пакет без тестов даёт `[no test files]`
и успех. Если завести CI до появления первых тестов, он будет зелёным всегда — и с `-race`
тоже, потому что детектору гонок нечего запускать. Проверять надо не «CI зелёный», а «CI
краснеет, когда я ломаю».

**Тестам `store` нужен настоящий Docker.** `testcontainers-go` поднимает Postgres контейнером;
если демон недоступен, эти тесты **падают с ошибкой подключения, а не пропускаются** — симптом
выглядит как поломка тестов, а не окружения. Остальные правила для таких тестов
(`flag.Parse()` первым делом в [`TestMain`](../plans/20260728-cartographers-m05.md#g-testmain),
закрыть все соединения перед снапшотом, база не называется `postgres`, без
[`t.Parallel()`](../plans/20260728-cartographers-m05.md#g-tparallel)) — в
[local-setup.md](../local-setup.md).

**Тесты на таймеры — через `testing/synctest`.** Тест, который ждёт настоящие секунды, на
раннере ведёт себя иначе, чем на ноутбуке: под `-race` всё медленнее, соседние job делят
процессор. Такой тест начинает мигать, а мигающий тест рано или поздно отключают.
`testing/synctest` прогоняет тридцать секунд игрового времени за ноль реального.

**Зелёный [golden-тест](../plans/20260728-cartographers-m05.md#g-golden) не доказывает, что
секрет не утёк.** `go test -update` спокойно перезапишет эталон вместе с утечкой, и тест
позеленеет — в CI поедет уже подделанный эталон. Поэтому рядом с golden нужна тупая проверка
«в готовом JSON нет вот этих подстрок», которую `-update` подделать не может.

**Сборка фронтенда в CI — не формальность.** Типы TypeScript пишутся руками, значит
переименование поля в Go само по себе ничего не ломает. Ловится это эталонным JSON-снапшотом,
который пишет тест на Go, и `satisfies` против него на стороне TS. Тогда переименование в Go
роняет сборку фронтенда, а не рисует пустое поле. Если job фронтенда из CI выкинуть «потому
что там всё равно только `npm run build`», проверка контракта исчезнет целиком.

## Готово, когда

- [ ] Push в ветку запускает прогон, обе job видны в PR
- [ ] Локально из `backend/` то же самое даёт тот же результат:
      `test -z "$(gofmt -l .)" && go vet ./... && go test -race ./...`
- [ ] Испорченный отступ в любом `.go` — CI красный: `test -z` действительно останавливает цепочку
- [ ] Временный `import _ "net/http"` в `internal/game` — тест чистоты падает и называет пакет
- [ ] Функция в `game`, принимающая тип из `internal/store`, — тест чистоты красный, при этом
      `golangci-lint run` зелёный. Это и есть смысл теста
- [ ] Переименовать поле в Go-структуре снапшота — падает сборка фронтенда
- [ ] Восемь пунктов чек-листа пройдены; после каждого `curl localhost:8080/healthz` отвечает
      `{"status":"ok"}` — сервер нигде не остался в упавшем состоянии
- [ ] devtools → Network: в потоке событий нет порядка колоды

Проверки «CI краснеет» удобно делать одним коммитом в отдельной ветке и потом её выбрасывать.
Пока не увидел красный прогон своими глазами, про CI ничего не известно.
